Screen inventory

  • Template Gallery (template-gallery) — Couple browses and selects an invitation template to start building.
  • Invitation Editor (invitation-editor) — Couple enters names, date, venue, photos, and greeting message onto the chosen template.
  • Guest View Preview (guest-preview) — Couple previews exactly what guests will see before publishing.
  • Publish and Share (publish-share) — Confirms the invitation is live and lets the couple copy the shareable link.
  • Guest Invitation Page (guest-invitation) — Guest opens the shared link (no login) and reads greeting, date, venue with map, and transport/parking guidance.
  • RSVP Form (rsvp-form) — Guest submits attendance with headcount and meal preference; lightweight for low-end phones.

Rationale summary

The six-screen inventory splits the PRD's two personas into a builder path (gallery > editor > preview > publish) and a guest path (invitation page > RSVP), with guest-preview and publish-share added beyond the four must-have screens so every flow-build step is clickable rather than implied. All screens live in one hash-routed HTML file with a flow-map landing view, keeping the prototype dependency-free and traceable edge-by-edge. Styling stays deliberately grayscale with hatched placeholders so review feedback targets structure and flow, not visual design.
