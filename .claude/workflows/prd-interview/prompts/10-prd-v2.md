# PRD v2 개정

먼저 Read 도구로 다음 파일을 모두 읽어라: `입력 > PRD 경로`(원문), `입력 > 페르소나 파일`, `입력 > 제품 설명서 파일`(기능 id 목록 포함), `입력 > 빠진 플로우 파일`(여정 걷기로 찾은, PRD가 빠뜨린 화면·플로우와 표준 제안), `입력 > 불편사항 파일`(통과/탈락과 사유), `입력 > 질문 파일`.

당신은 이 PRD의 소유자다. 페르소나 인터뷰 결과와, 질문 파일의 각 질문에 대한 `입력 > 답변`(PRD 소유자가 직접 답한 것)을 반영해 PRD를 v2로 개정하라. 원 PRD의 구조(배경, 유저스토리, 상황, 기능 요구사항, 조건)를 유지하되 내용을 고친다. 규칙:

- 제품 설명서의 기능 id를 기준으로, 기능 요구사항 각 항목 끝에 [유지] [수정] [추가] [삭제] 중 하나를 표시하고, 수정/추가/삭제에는 근거를 붙인다. 근거 형식: 인터뷰에서 나온 것은 `근거: <페르소나> — "<인용>"`, 답변에서 나온 것은 `근거: 소유자 답변 <질문 id>`.
- 빠진 플로우 파일의 항목은 기능 요구사항에 새 항목으로 [추가]한다. mode가 baseline이면 제안(proposal)을 그대로 요구사항으로 쓰고 `근거: 여정 걷기 <F0-id>`, 소유자 답변이 있으면 답변을 따르고 `근거: 소유자 답변 <질문 id>`. mode가 interview인 항목은 인터뷰 불편사항과 답변을 근거로 쓴다.
- `입력 > 답변` 중 id가 `Q-free`인 것은 소유자의 자유 의견이다. 어떤 근거보다 우선한다. 새 요구사항이 들어 있으면 기능 요구사항에 [추가]하고 `근거: 소유자 의견 Q-free`를 붙인다. 방향에 대한 언급이면 전체 개정에 반영하고 "소유자 결정 사항" 표 마지막 줄에 원문을 남긴다. "없음"이면 무시한다.
- `입력 > 답변`은 인터뷰 추론보다 우선한다. 답변이 불편사항과 충돌하면 답변을 따르고, 그 불편사항은 "미해결 트레이드오프"에 소유자 결정과 함께 남긴다.
- 유저스토리는 페르소나별 인터뷰에서 확인된 것으로 갱신한다. 원 PRD에 없던 역할이 페르소나에 있으면 추가한다.
- 새 섹션 **설계 시 유의사항**: 화면·흐름을 설계할 때 반드시 지켜야 할 것을 항목별로, 각 항목에 관련 불편사항 id를 붙인다.
- 새 섹션 **미해결 트레이드오프**: 답변으로 정리되지 않은 페르소나 간 충돌을 양쪽 입장과 함께 남긴다.
- 새 섹션 **소유자 결정 사항**: 질문 id, 질문, 답변을 표로 정리한다.
- 새 섹션 **개정 이력**: 인터뷰 횟수, 페르소나 목록, 통과/탈락 불편사항 수, 다뤄지지 않은 기능 (불편사항 파일 머리 참고).
- 검증에서 탈락한 항목은 근거로 쓰지 마라.
- 제출/평가 관련 원문 섹션은 그대로 둔다.

결과 파일은 Write 도구로 `입력 > 저장 경로`에 저장하라 (한국어).
